# Celular Integration Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

## Goal

Bring the standalone Celular Paper plugin (package `dev.linqfy.celular`, built and playtested separately) into
BigCasares as the `celular` module, reusing BigCasares' module lifecycle and Java resource pack instead of the
standalone plugin's own main class and HTTP pack server.

## Tech Stack

- Paper API 26.2.build.56-alpha, Java 25, Gradle 9.2.1.
- Unit tests: JUnit 5 against `spigot-api:26.2-R0.1-SNAPSHOT`.
- Asset generators: Python 3 + Pillow + NumPy, ffmpeg for the videos (`tools/celular/`).

## File Structure

New:
- `src/main/java/dev/linqfy/bigCasares/modules/celular/*.java`: 11 classes (see the design spec).
- `src/test/java/dev/linqfy/bigCasares/modules/celular/*Test.java`: 7 test classes.
- `src/main/resources/celular/videos.yml`: bundled video list (generated).
- `resourcepack/java/assets/celular/`: item definitions, models and textures (generated).
- `tools/celular/`: `generar_celular.py`, `convertir_videos.py`, `generar_bedrock.py` and previews.
- Bedrock: `resourcepack/bedrock/{models/entity/celular.geo.json, animations/celular.animation.json,
  textures/entity/celular_bedrock.png, attachables/celular_*.json}` and the icon
  `resourcepack/shared/textures/item/celular_bedrock.png` (generated).
- `docs/superpowers/specs/2026-10-04-celular-design.md`, this plan and the user guide `docs/celular/README.md`.

Modified:
- `BigCasares.java`: construct, register and expose `CelularModule`.
- `README.md`: short Celular section linking to `docs/celular/README.md`.
- `config.yml`: `modules.celular.enabled: true` and the `celular:` section.
- `plugin.yml`: `/celular` command (alias `/celu`) and `bigcasares.celular.admin` (also a child of `bigcasares.*`).
- `GeyserIntegrationModule.java`: also registers the phone's Geyser custom items (`celularItemDefinitions()`).
- `GeyserRuntimeBridge.java`: subscribes to each Geyser event explicitly; annotated handlers were ignored whenever
  Floodgate was installed (see the design spec). New `GeyserEventSubscriptionContractTest` guards it.
- `resourcepack/shared/registry.yml`: `celular` entry for the Bedrock inventory icon.
- `.gitignore`: `tools/celular/videos/` (source videos are not committed).

## Boundaries

- No changes to `build.gradle` or to the resource-pack module code.
- Changes to another module: the phone's item list in `GeyserIntegrationModule` (reached through
  `BigCasares#getCelularModule()`) and the event-subscription fix in `GeyserRuntimeBridge`.

### Deviations from plan
- Developed and playtested as a standalone plugin first, then integrated.
- No `CelularStorage`: the only persistent state is the per-village flag, stored in the village's own
  `GeneratedStructure` persistent data container, and the video index stored on each item.
- Bedrock went through three versions in this PR: D-pad controls, then a plain clock, and finally the 3D phone with
  "Pobre" on the screen, which needed a small change in `GeyserIntegrationModule` (outside the original boundaries).
- Verified on a live isolated server (see task 5): recipe, crafting, commands, village loot and the Geyser
  registration. That run found the Floodgate/`@Subscribe` bug in `GeyserRuntimeBridge`, which was fixed here because
  without it no Bedrock player would see the phone (or any other BigCasares custom item).

### Known limitations
- Videos are silent and do not restart when switched (client-side animated textures).
- ~170 MB of client texture memory for the bundled videos; the Java pack grows by ~28 MB, and the current jar packaging
  bundles the pack several times (jar ~88 MB).
- Bedrock players see the phone in 3D with "Pobre" on the screen and get the message "Dale bobi, no tenes java?,
  bancatela pibe" when crafting it; it plays no videos for them. The Bedrock model and its hand positions were
  converted with the java2bedrock rules and never checked with a Bedrock client (Geyser loads and registers them
  without errors, but how they look in the hand can only be checked from Bedrock).
- The live checks ran with Vault and the economy modules (mission, bounty, shop) off; BigCasares still needs Vault
  for those, as before.
- Source videos are not committed (`tools/celular/videos/` is ignored).
